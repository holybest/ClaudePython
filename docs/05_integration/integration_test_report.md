| 기준 문서 | SWAD-ECL-001 개정 0.3 (인터페이스·동적 동작·간섭 방지), SWRS-ECL-001 개정 0.3 |

## 1. 통합 전략
- 단위 시험을 통과한 유닛을 SWAD의 실제 구성(`create_service`, `make_server`)으로 연결한다. 가짜 객체 없이 **실제 단조 시계, 실제 tick 스레드, 실제 HTTP 서버**를 쓴다.
- 시간 관련 요구(입력 중단 감시, tick 주기, 처리 시간)는 PC 실측으로 확인한다(SWAD 6.3: PC/SIL 한계).
- 별도 프로세스 실행(ITC-06, 07)으로 실행 진입점과 비영속성을 확인한다.
- 시험 환경: Windows 11, Python 3.12.10 / 3.14.10, Jenkins `ClaudePython-CI`.

## 3. 측정값 (PC/SIL, 10회·1,000회 측정)

| 항목 | 요구 | Python 3.12 | Python 3.14 |
|---|---|---|---|
| 입력 중단 → `DEGRADED` | ≤ 300 ms (OEM-SR-003: 200 ms 초과 후 100 ms 이내) | 203 ~ 250 ms | 201 ~ 261 ms |
| tick 스레드 간격 (HTTP 부하 중) | 평균 50 ms (SWR-022), 최대 ≤ 100 ms (SWAD 6.1) | 평균 49.8 ms, 최대 63.8 ms | 평균 49.9 ms, 최대 63.1 ms |
| 1회 평가 처리 시간 | ≤ 10 ms (SWR-023) | 평균 0.05 ms, 최대 0.21 ms | 평균 0.07 ms, 최대 0.22 ms |

## 4. 통합 중 발견한 결함과 조치

| # | 결함 | 발견 경위 | 조치 | 상태 |
|---|---|---|---|---|
| I-01 | tick 스레드 실제 주기가 62.5 ms로 SWR-022(50 ms 이하 주기)를 만족하지 못함. Windows 대기 분해능(약 15.6 ms) 때문에 50 ms 대기가 62.5 ms로 늘어남 | ITC-03 측정 | 고정 대기 대신 다음 예정 시각까지 남은 시간만 대기(평균 주기 50 ms 유지, 크게 밀리면 재기준). 재현 단위 시험 추가(1초당 19~22회) | 완료 |
| I-02 | ITC-03이 상태 조회로 실행된 tick까지 세어 tick 스레드 주기를 검증하지 못함 (시험 결함) | 측정값 이상(평균 1.1 ms) 분석 | tick 스레드에서 실행된 것만 측정 | 완료 |
| I-03 | 부하 시험이 클라이언트 임시 포트를 고갈시켜 간헐 실패 가능(WinError 10048, 시험 환경 문제) | 반복 측정 | 부하 클라이언트에 5 ms 간격 | 완료 |

I-01은 4단계 단위 시험으로 드러나지 않은 실제 실행 환경의 결함이다. OEM 시간 요구(300 ms)는 수정 전에도 만족했으나(최대 250 ms), SWR-022의 tick 주기 조건을 지키지 못했다.

## 5. 결론
- SWAD의 모든 컴포넌트 인터페이스와 동적 동작이 실제 구성에서 설계대로 동작함을 확인했다.
- 시간 요구는 PC/SIL 실측으로 만족한다. 양산 ECU의 실행 시간 보장은 범위 밖이다(OEM 3장).
- 전체 시험 340건(단위 328 + 통합 11 + 아키텍처 1) 통과, 분기 커버리지 100%.
