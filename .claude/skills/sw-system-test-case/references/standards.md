# 표준 요건 요약

테스트 케이스가 아래 요건을 만족하는지 확인하는 기준으로 쓴다. 조항 번호보다 "무엇이 증거로 요구되는가"에 집중한다.
조항·표 번호는 표준 버전에 따라 다를 수 있으므로, 산출물에 인용할 때는 사용자가 쓰는 표준 버전을 확인한다.

## A-SPICE — SW 수준 시험 (SWE.6)

- A-SPICE 3.1: **SWE.6 Software Qualification Test**
- A-SPICE 4.0: **SWE.6 Software Verification**

시험 케이스(verification measure)에 요구되는 내용:

| 요건 | 테스트 케이스에 반영하는 방법 |
|---|---|
| SW 요구사항을 근거로 시험 사양 작성 | 모든 케이스에 테스트 베이시스 ID |
| 시험 기법, 사전조건/진입 조건, 합격/불합격 기준 명시 | `사용한 테스트 기법`, `사전조건`, `합격/불합격 기준` 열 |
| 시험 환경 명시 | `시험 환경` 열 또는 문서 전체에 공통 기재 |
| 시험 케이스 선택 근거 (회귀 시험 포함) | 우선순위, 기법별 도출 근거 |
| 요구사항 ↔ 시험 케이스 **양방향 추적성** | 추적성 매트릭스 시트 |
| 요구사항과 시험 케이스의 **일관성** | 각 케이스가 베이시스의 의도를 실제로 검증하는지 검토, 모순은 검토 의견에 기록 |
| 결과 요약 및 전달 | 커버리지 요약 시트, 최종 보고 |

## ISO 26262 Part 6 — 임베디드 SW 시험

ISO 26262-6:2018은 Clause 11 "Testing of the embedded software"에서 SW 수준 시험을 다룬다.

### 시험 방법
- **요구사항 기반 시험**: 모든 케이스는 SW 안전 요구사항/SW 요구사항에서 도출한다.
- **고장 주입 시험(fault injection)**: 높은 ASIL에서 강하게 권장된다. 예: 센서 값 고착·범위 밖 값, 통신 메시지 손실·CRC 오류·Alive counter 오류, 메모리 손상, 타이밍 초과. 안전 메커니즘(감지 → 반응 → 안전 상태 진입, FTTI 이내)을 검증한다.

### 시험 케이스 도출 방법
- 요구사항 분석
- **동치 클래스** 생성 및 분석
- **경계값** 분석
- 지식·경험 기반 오류 추측 (error guessing) → 이 스킬에서는 `WoW 검증` 엣지 케이스로 다룬다
- 기능 의존성 분석
- 운용 사용 사례(operational use case) 분석

### 시험 환경
- HIL, ECU 네트워크 환경, 실차 등. 대상 하드웨어에서 실행하는 것이 원칙이다. 케이스의 입력·관찰 신호는 선택한 환경에서 실제로 다룰 수 있어야 한다.

### 커버리지
- 요구사항 커버리지: 모든 SW (안전) 요구사항이 시험으로 검증되어야 한다. 이 스킬의 "베이시스 커버리지 100%"에 해당한다.

## 안전 관련 요구사항 체크

ASIL이 붙은 베이시스 항목에는 다음을 확인한다.
- 안전 메커니즘의 감지 조건, 반응 시간(FTTI 이내), 안전 상태 진입·유지·복구 조건을 각각 시험하는 케이스가 있는가
- 고장 주입 케이스가 있는가 (없다면 이유를 검토 의견에)
- 정상 동작만이 아니라 고장 조건이 사라진 뒤의 복구 동작도 시험하는가
