## 상세

### UC-01 운전자 잠금·해제
- **사전조건**: 시동 ON, 모든 입력 유효, 충돌·센서 고장 없음.
- **기본 흐름**: 운전자가 `side`·`action`·`source`로 명령 → SW가 선택된 쪽 출력만 변경 → 이유 `DRIVER_LOCK`/`DRIVER_UNLOCK`.
- **대안 흐름**
  - A1 명령 형식 오류·미등록 값 → 출력 유지, `COMMAND_REJECTED` (SWR-002)
  - A2 해제 금지 조건(차속 ≥ 3.0 km/h, 접근위험, ISOFIX) → 그 쪽 유지, `DRIVER_UNLOCK_REJECTED` (SWR-004)

### UC-02 주행 시작 자동 잠금
- **사전조건**: 시동 ON, 정지 상태, 출력 임의.
- **기본 흐름**: 차속이 3.0 km/h 이상이 됨 → 같은 주기에 좌·우 `LOCK`, `AUTO_LOCK_SPEED`.
- **대안 흐름**: A1 차속이 다시 3.0 km/h 미만 → `LOCK` 유지 (SWR-003).

### UC-03 접근위험 하차 억제와 override
- **사전조건**: 시동 ON, 정지, 출력 `RELEASE`.
- **기본 흐름**: 한쪽 접근위험 TRUE → 그 쪽 `LOCK`, `APPROACH_RISK` → 운전자가 그 쪽 해제 요청 → 억제(`UNLOCK_SUPPRESSED`), t0 기록.
- **대안 흐름**
  - A1 10,000 ms 이내 같은 쪽 재요청(새 입력) → 그 쪽 `RELEASE`, 상태 `OVERRIDE`, `APPROACH_OVERRIDE`. 위험이 FALSE가 될 때까지 유지 (SWR-006)
  - A2 10,000 ms 초과 후 재요청 → 다시 억제, t0 갱신
  - A3 같은 명령이 연속 스냅샷에 남아 있음 → 재요청으로 보지 않음
  - A4 반대쪽은 영향 없음 (SWR-009)
  - A5 안전 입력 이상(DEGRADED) 중 재요청 → override 불가

### UC-04 충돌 긴급해제
- **사전조건**: 시동 ON, 출력 임의(주행 중 `LOCK` 포함).
- **기본 흐름**: `crash_status = CONFIRMED`(IF-002 형식 유효. 스냅샷 지연, 다른 입력 무효, 센서 고장과 무관) → 같은 주기에 좌·우 `RELEASE`, 상태 `EMERGENCY`, `CRASH_CONFIRMED` → 이후 모든 입력과 무관하게 유지 → 시동 OFF에서 래치 해제.
- **대안 흐름**: A1 `PENDING` → 출력 영향 없음, `CRASH_PENDING` (SWR-008).

### UC-05 화재·과온·성인 탑승 강제해제
- **사전조건**: 시동 ON, 출력 `LOCK`.
- **기본 흐름**: 세 입력 중 하나가 TRUE → 같은 주기에 좌·우 `RELEASE`, 입력별 이유 코드.
- **대안 흐름**: A1 접근위험이 TRUE인 쪽은 `LOCK` 유지 (SWR-019 우선순위 3 > 6, 질의 Q-02).

### UC-06 ISOFIX 강제잠금
- **기본 흐름**: 한쪽 ISOFIX TRUE → 그 쪽 `LOCK`, 반대쪽 유지, `ISOFIX`.
- **대안 흐름**: A1 그 쪽 해제 명령 → 거절. A2 ISOFIX FALSE → `LOCK` 유지 (SWR-018).

### UC-07 시동 OFF
- **기본 흐름**: `ignition_on = FALSE` → 먼저 충돌 래치와 override 초기화 → 같은 평가에 좌·우 `RELEASE`, 상태 `OFF`, `IGNITION_OFF`.
- **대안 흐름**: A1 같은 스냅샷에 CONFIRMED → 래치 재설정, `EMERGENCY` (SWR-020). A2 접근위험·센서 고장·안전 입력 이상이 함께 있으면 상위 규칙 우선 (SWR-019, 질의 Q-02).

### UC-08 입력 이상 대응
- **기본 흐름**: 안전 입력 그룹(IF-002/003/009) 무효 또는 스냅샷 지연(> 200 ms) → 같은 평가에 `DEGRADED`, 상위 규칙이 결정하지 않은 쪽은 직전 출력 유지.
- **대안 흐름**
  - A1 입력 중단(수신 없음) → 50 ms tick 평가에서 지연 검출, 중단 후 300 ms 이내 `DEGRADED` (SWR-022)
  - A2 `sensor_fault = TRUE` → `FAULT`, 직전 출력 유지, `W_SENSOR_FAULT` (SWR-021)
  - A3 이상 중 충돌 CONFIRMED(IF-002 형식 유효) → `RELEASE` (SWR-019 순위 1)
  - A4 이상 중 접근위험 TRUE → 해당 쪽 `LOCK` (순위 3)
  - A5 IF-001/004/007/008만 무효 → `DEGRADED` 아님, 해당 규칙만 비활성
  - A6 모든 안전 입력 그룹 유효, 지연 없음 → 정상 평가로 복귀

### UC-09 상태 조회와 결정 이력
- **기본 흐름**: 시험자가 Web 화면(`GET /`) 또는 `POST /api/snapshot`으로 입력 → `GET /api/status`로 출력·상태·유효성·이유·알림 확인 → `GET /api/events`로 최근 100건 확인.
- **대안 흐름**
  - A1 JSON이 아닌 요청 본문 → 400 (SWR-015)
  - A2 정의되지 않은 필드(영상·음성·이름 등) 포함 → 400, 처리·저장 없음 (SWR-026)
  - A3 직렬화 실패 → 500 (SWR-015)
