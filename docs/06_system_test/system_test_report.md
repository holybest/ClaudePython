## 1. 시험 방법
- **케이스 설계**: `sw-system-test-designer` 에이전트(`sw-system-test-case` 스킬)가 SWRS만을 근거로 설계했다(구현 코드는 보지 않음). 동치 분할, 경계값 분석, PICT 페어와이즈(SWR-001, SWR-019), 상태 전이, 결정 테이블, 고장 주입, WoW 검증(엣지)을 적용했다. 추적성·베이시스 커버리지 100%를 스킬 스크립트로 검증했다.
- **실행**: 납품 형태 그대로 시뮬레이터를 **케이스마다 새 프로세스로 기동**하고 HTTP(`POST /api/snapshot`, `GET /api/status`, `GET /api/events`)로만 입력·관찰했다(블랙박스). 화면 케이스(STC-F-162, 163)는 헤드리스 Edge로 실제 화면을 조작했다.
- **자동화**: 케이스를 4개 범위로 나눠 별도 에이전트가 pytest로 옮겼다. 실패 시 기대값을 구현에 맞춰 바꾸지 않고 원인을 분류해 보고하게 했으며, 최종 판정(구현 결함/케이스 결함/환경 한계)은 개발 책임자(Claude)가 했다.
- **환경**: Windows 11, Python 3.12.10(CI) / 3.12·3.14(로컬), Jenkins `ClaudePython-CI`.

## 5. 자동화 시 해석한 사항 (케이스 문구 보완 권고)
- **"응답과 직후 GET /api/status 확인"**: 상태 조회는 서버가 tick을 1회 수행하므로 이유 코드가 `NO_CHANGE`로 바뀐다(SWR-022). 기대값 전체는 POST 응답으로 판정하고, 직후 상태 조회는 출력·상태만 확인했다. 케이스 문구에 이 구분을 명시할 것을 권고한다.
- **notices 비교**: 케이스 합격 기준대로 집합으로 비교했다(순서 무관).
- **override 창 경계(0 / 10,000 / 10,001 ms)**: `source_timestamp_s`를 직접 지정하고, 서버 시각이 그 값을 지난 직후 전송해 미래 시각 STALE을 피했다. 대기 중에는 100 ms 이하 주기로 같은 입력을 보내 입력 중단을 막았다(KA).
- **지연 경계(STC-F-100, 101)**: 서버 시각을 주입할 수 없어 응답 `timestamp_s`로 사후 판정하는 표본 방식으로 실행했다. 표본 부족은 '시험 불성립'으로 실패 처리한다.

## 6. 남은 검토 의견 (OEM 확인 필요)
케이스 설계 중 기록한 검토 의견 22건 중 동작에 영향이 있는 항목은 다음과 같다. 모두 SWRS의 현재 가정(A-13 우선순위 등)대로 시험했고 통과했다. 실제 OEM 답변에 따라 요구사항이 바뀔 수 있다.
- 센서 고장(순위 2) 중에는 접근위험 TRUE여도 잠그지 않는다(SWR-005와 SWR-021의 우선순위, 질의 Q-02 g).
- 주행 중(3.0 km/h 이상) 시동 OFF에서 좌·우가 해제된다(순위 5 > 8). 안전 관점의 재검토를 권고한다(질의 Q-02에 추가 권고).
- 입력 그룹 단위 무효화(DEF-07)로 접근위험 한쪽 신호만 손실돼도 양쪽 위험 판단이 비활성된다. 쪽별 유효성으로 세분화하는 개선을 권고한다.
- SWR-015의 HTTP 500(직렬화 실패)은 블랙박스로 주입할 수 없어 단위 시험(`test_web.py`)으로만 검증했다.

## 7. 결론
- SWRS SWR-001~026 전체가 시스템 시험으로 검증되었다(로컬 174/174 통과, NF-002 사양 값 1,000회 포함).
- **CI 미해결 사항**: 화면 케이스 2건(STC-F-162, 163)은 Jenkins 서비스 계정(LocalSystem)에서 브라우저를 실행할 수 없어 CI에서 실패한다. 해결 방안: (1) Jenkins 서비스를 일반 사용자 계정으로 실행하도록 변경, 또는 (2) 화면 케이스를 CI 대상에서 분리하고 로컬 실행 결과를 정식 증거로 관리. 어느 쪽이든 사용자 결정이 필요하며, 결정 전까지 CLAUDE.md 병합 조건(CI 통과)을 만족하지 못해 6단계 PR은 병합하지 않는다.
- 시스템 시험에서 구현 결함 2건과 요구사항 추적성 결함 1건을 발견해 수정했다. 수정은 재현 시험을 먼저 추가한 TDD로 했고, 단위·통합 시험(342건)과 시스템 시험(174건)을 다시 통과했다.
- 미검증 범위: HIL, 실차, 타깃 ECU, 양산 HMI(OEM 문서상 범위 밖). 시간 요구는 PC 실측으로만 확인했다.
